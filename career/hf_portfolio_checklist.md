# Hugging Face Portfolio Checklist

Use this checklist before applying. The goal is to make your application feel like a finished product, not just a resume.

## Must-Have Links

- Live Hugging Face Space for `nsys-llm-explainer`
- GitHub repo for the code
- README with clear screenshots and a concise value proposition
- One technical blog post or long-form writeup
- One short video demo or webinar recording
- One deployment guide for a cloud target

## Must-Have Assets

- `README` headline that says exactly what the project does in one sentence
- 3 to 5 screenshots showing the main workflow and the best “wow” panels
- A sample trace and a baseline trace for comparison
- A reproducible deployment path, ideally containerized
- A small benchmark table with real numbers
- A concise “how to use this” section for first-time users

## For The Cloud ML Engineer Role

- Show cloud deployability: Docker, environment variables, managed-service compatibility, and monitoring hooks.
- Show performance literacy: latency, throughput, utilization, bottleneck analysis, and clear tradeoffs.
- Show reliability: warnings, failure modes, and behavior when counters or trace fields are missing.
- Show API thinking: CLI, JSON, CSV, and any service wrapper.

## For The Cloud ML DevRel Role

- Show teachability: one notebook, one blog post, one short demo video.
- Show public usefulness: a live Space that works without local setup.
- Show clarity: explanations for what the tool does and what it does not infer.
- Show community impact: one upstream contribution, one docs improvement, or one example repo users can copy.

## Metrics To Include

- `<N>` traces analyzed
- `<M>` GPU profiles or workloads tested
- `<X%>` improvement in setup time, investigation time, or throughput after an optimization
- `<Y>` minutes from upload to actionable insight
- `<Z>` public artifacts shipped

## Final Quality Bar

- If a recruiter opens one link, they should immediately understand the problem, the demo, and the engineering depth.
- If an engineer opens the repo, they should see clean code, reproducible outputs, and clear limitations.
- If a DevRel reviewer opens the Space, they should see a demo worth sharing.
